## Screens and actions

Mac Sync is a regular macOS app with a status item in the system menu bar. It uses the existing CLI and the same configuration and snapshot repositories, so there is no separate sync implementation. A local SQLite index pages the portable JSON history; neither index nor history is pushed to GitHub.

- **Overview** shows the last completed sync, live activity, warnings, errors, the snapshot footprint for this Mac, and the available peer snapshots. It distinguishes a complete sync, a usable partial sync with a skipped optional subsystem, and a failed sync that stopped before unsafe writes. An active warning or error appears in the Sync Health card instead of being repeated on the dashboard. While live health checks run, recorded conditions are shown as neutral rather than requesting remediation; recovered warnings remain visible as green history under Last sync health.
- **This Mac** lists the configured snapshot roots and every regular file and folder currently stored for the local machine. The configurable outline and archive browser behave like purpose-built file managers: expand or collapse configured roots and open archive folders on demand, select items, copy paths, reveal archived copies in Finder, and use the contextual actions to preview or inspect files. Both retain the exact selected roots in `sync-paths.txt`. A saved root can be removed from both the archive and Sync Selection after confirmation; the original source file is not deleted. Encrypted secrets are shown separately: a trusted recipient can use **View Encrypted Secrets** to list archive file and folder names. The app never displays secret values.
- **Other Macs** offers the same archive browser and lets you choose exact files or folders, preview their copy, then copy only those paths from the source snapshot in `mac-sync-data` into this Mac. The source archive is not changed. When a peer has encrypted secrets, trusted recipients can inspect its archive entries before deciding whether to restore them in Terminal. A manual copy always asks whether to keep this Mac's existing files or replace them with the selected peer snapshot.
- **Sync Selection** starts from `machines/<this-Mac>/config/sync-paths.txt`. Select files and folders from the Mac, drag or paste files from Finder, expand or collapse parent folders, reveal and copy selected roots, remove several at once, save it, then sync it. Folders are copied subject to that Mac's `config/excludes.txt` rules.
- **Sync History** keeps a local, per-run ledger of sync and restore attempts, including failed, deferred and local-only runs. Its headings do not imply a successful GitHub upload. It shows file-level snapshot transfers, whether an item was new, updated, removed, or skipped, and the source and destination paths. Failed network attempts are recorded as bounded, credential-redacted command diagnostics. Preview runs are deliberately not added to the history.

  Before a sync changes snapshots, Git must confirm the data repository's named branch. Mac Sync checks again before committing. A confirmed detached HEAD and a failed branch command are separate errors; neither triggers an automatic branch switch or reset. Review the recorded exit status and command output when a branch check fails. Existing history remains a record of the original run and is not rewritten by an upgrade.

- **Sync Health** separates active health from history. It checks recorded GitHub and encrypted-secrets conditions again, automatically marks conditions as recovered when the underlying check passes, and retains old occurrences under **All**. Checks run after explicit actions, not each time you open the app. Temporary network failures wait for a saved retry; repeated outages become actionable after three failed attempts. Active conditions offer actions such as testing GitHub, switching the data repository to verified SSH, testing encrypted secrets, opening Keychain Access, or retrying sync. Notes and acknowledgements remain local under `status/issues/` and are never synced. Explicit health checks can verify that the Keychain item exists through a metadata-only lookup; conditions that require decryption stay active until the user explicitly runs **Test Encrypted Secrets**.
- **Automatic sync** in Settings installs a per-user `launchd` schedule. Add one or more day-and-time entries, including multiple times on the same day, choose a preset interval, or use a custom interval; Mac Sync keeps the schedule local and never stores credentials in launch agents. The UI need not run. The worker defers during Low Power Mode, serious thermal pressure or a memory-pressure warning. Manual **Sync Now** still performs a full inventory and the interactive encrypted-archive checks.

The menu-bar item gives quick access to the dashboard, current status, sync, stop, refresh, About, and repository setup actions. By default the running app stays in the menu bar without adding a Dock icon; **Settings → App appearance** can restore the Dock icon. During an active sync, the menu-bar status icon and the blue dashboard status icon rotate until the run finishes. The app's settings view shows the active repository and status paths, lets you re-run local setup, and includes a non-interactive GitHub read/write check. It never stores a GitHub token: the check uses the Mac's existing Git authentication and redacts credentials from its output.
